# Cascade Solitaire

Phaser-пасьянс с механикой Sawayama Solitaire. Внешний продуктовый слой использует общий Phaser UI-kit: Home, Daily, Mastery, Leaderboards, Settings, How to Play и продуктовые модалки работают в едином responsive layout. Сам карточный стол, правила, drag/drop и анимации Cascade остаются отдельным gameplay core.

Экраны обращаются к европейским/ботаническим арт-ассетам через семантические ключи `CascadeUiArt`, поэтому визуал можно заменять без перестройки layout. Standard использует явные Easy/Medium/Hard, а долгосрочная прогрессия строится на Mastery, Daily и таблицах лидеров. Игровой стол использует одну фиксированную appearance-схему и рубашку `public/assets/cards/redBack.webp`.

## Что работает

- оригинальная схема поля: четыре базы слева, колода над первым столбцом,
  сброс веером вдоль верхней строки;
- карты из набора `Horizontal2`, tableau поднят выше для лучшей читаемости масти;
- runtime-карты снова загружаются как обычные PNG; текущие Horizontal2 лица заранее подготовлены в 216×302 (2× от игрового 108×151), поэтому Phaser только уменьшает готовую текстуру и не использует runtime SVG-loader;
- на десктопе реальный Phaser canvas заполняет всё окно через `Scale.RESIZE`, без CSS-растягивания фиксированного canvas;
- игровая геометрия рассчитывается напрямую из текущего viewport через `LayoutMetrics`; камера всегда остаётся `zoom = 1`, `scroll = 0`;
- desktop-layout гибридный: карты умеренно растут от базового размера до 180×252, tableau держит компактные интервалы около 30% ширины карты, а лишнее widescreen/ultrawide-пространство остаётся вокруг центрированной группы колонок;
- пустой прямоугольник справа от колоды удалён;
- стартовая раздача и остальные автоматические перемещения летят по неглубокой дуге;
- открытие колоды по три карты с сохранением оригинальной логики Hikone;
- перенос одной карты и упорядоченных убывающих цепочек drag-and-drop;
- сбалансированная drop-зона: ход принимается примерно от 25% перекрытия цели; лёгкое касание краем или уголком не засчитывается;
- drag-and-drop вообще не использует финальную анимацию: успешный дроп мгновенно фиксирует карту/цепочку в новой позиции, а неудачный/отменённый мгновенно возвращает её на прежнее место;
- сбор баз по масти от туза до короля;
- свободная ячейка на месте опустевшей колоды;
- двойное нажатие по доступной карте отправляет её в базу;
- автоматический перенос безопасных карт в базы, включая карты выше тузов;
- предыдущая карта в foundation остаётся видимой под следующей во время автоматического перелёта;
- отмена последнего полного действия кнопкой `ОТМЕНА` или клавишей `Z`;
- один undo откатывает действие игрока вместе со всей вызванной им цепочкой
  автоматических переносов в базы;
- рестарт той же раздачи кнопкой `РЕСТАРТ` или клавишей `R`;
- `НОВАЯ ИГРА` / `N` сразу запускает новый seed в текущем режиме;
- отдельное `В МЕНЮ` открывает главное меню выбора принципа раздачи;
- верхние кнопки и главное меню используют native DOM/HTML-текст вместо Phaser Text, чтобы мелкие подписи были резче; DOM UI живёт прямо в viewport и не зависит от Phaser-layout;
- смена режима применяется только после нажатия `ИГРАТЬ`;
- `Escape` закрывает главное меню, если за ним уже есть текущая партия;
- два режима: точный оригинальный и гарантированно решаемый;
- уведомление `LoadingAPI.ready()` при запуске внутри Яндекс Игр.

Оригинальный режим побитно воспроизводит найденные в исходниках Hikone 64-битный
генератор случайных чисел, Fisher–Yates, повторную перетасовку, направление
раздачи и правило открытия трёх карт. Среди семи стартовых открытых карт нет
тузов и сразу совместимых разноцветных пар соседних рангов. Как и в оригинале,
редкие нерешаемые партии в этом режиме возможны.

Гарантированно решаемый режим выбирает только из 512 seed’ов, для каждого из
которых офлайн-решатель нашёл полный путь до всех четырёх королей. Решатель не
работает в браузере и не влияет на скорость игры.

## Управление

- `В МЕНЮ` — открыть главное меню и при необходимости сменить режим;
- `N` — новая раздача в текущем режиме;
- `Z` — отменить последнее полное действие;
- `R` — перезапустить текущий seed;
- `Esc` — закрыть главное меню и вернуться к текущей партии.

Пока главное меню открыто, `N`, `Z` и `R` не меняют игровое состояние.

## Структура

- `src/game/model` — чистые правила, карты, история undo и генерация раздачи без Phaser;
- `src/game/view` — геометрия поля, карточные объекты, ввод, меню и анимации;
- `src/game/scenes` — координация flow, истории и игрового состояния;
- `src/platform` — изолированная интеграция с игровой платформой;
- `docs/superpowers/specs` — утверждённые спецификации предыдущих этапов;
- `docs/superpowers/plans` — детальные планы реализации.

## Запуск

```bash
pnpm install
pnpm dev
```

Runtime не зависит от SVG-конвертации или генерации ассетов перед `dev`/`build`. Исходные наборы в `Decks/` можно хранить только как source art для будущих замен.
После изменений рендера/viewport dev-сервер нужно один раз перезапустить.

Проверки и production-сборка:

```bash
pnpm test
pnpm build
```

## Контекст для нового чата ChatGPT

Для текущего рабочего состояния, включая незакоммиченные изменения:

```bash
pnpm context
```

Для последнего коммита/checkpoint:

```bash
pnpm context:last
```

Команды обновляют `TREE.txt` и перезаписывают `_chatgpt_bundle/CHATGPT_CONTEXT.txt`.
В новый чат достаточно отправить этот файл; постоянные правила и состояние берутся из
`PROJECT.md`, `CURRENT_STATE.md` и `TECH.md`.

Повторная генерация проверенного пула (нужен C++20-компилятор по пути,
указанному в `package.json`):

```bash
pnpm generate:winnable-pool
```

В пул записываются только результаты `SOLVED`; раздачи `UNSOLVABLE` и
`UNDETERMINED` в приложение не попадают.
