# Темы игрового стола

Тема — один комплект: поверхность, рубашка, четыре основания по мастям, пустой столбец, свободная ячейка и палитра игровых кнопок. Лица карт, правила, раскладка и оформление главного меню независимы от темы.

## Добавление темы

1. Положите файлы в `public/assets/themes/<theme-name>/`.
2. Добавьте запись в `THEMES` в `src/theme/ThemeRegistry.ts`. Ключ записи и `id` должны совпадать. `ThemeId`, проверка идентификатора и `getThemes()` используют этот реестр — дополнительный список не нужен.
3. Задайте `boardSurface`, `cardBack`, `surfaceScale`, `slots` и `controls`. Ключи текстур должны быть уникальными, пути — относительными (`./assets/...`).
4. Для фона используйте `cover` (вписывание с центральной обрезкой без искажения пропорций) либо `tile` (повторение бесшовной фактуры в исходном масштабе). У Walnut Study фон не содержит кромок, бортиков или рамок по периметру.
5. Для `slots.kind: 'vector'` достаточно палитры `recess`, `edge`, `highlight`, `blackSuit`, `redSuit`. Общий SVG-шаблон автоматически создаёт все шесть вариантов. Для авторских изображений используйте `slots.kind: 'images'` и полный `assets`, как у Green Felt Club. Пропорции слота — 216 × 302, прозрачный фон, весь рисунок внутри границ карты. Рекомендуемый размер растров — 432 × 604.
6. Задайте цвета `controls`: `surface`, `hover`, `ink`, `edge`, `labelSurface`, `labelInk`, `focus`.
7. Проверьте тему через `/?theme=<id>`, затем тесты и сборку. Посмотрите размеры 1915 × 953, 1366 × 768 и 844 × 390; обязательно проверьте пустой столбец и пустую колоду.

## Загрузка и переключение

`getThemeAssets(theme)` — единый список ресурсов для предварительной и последующей загрузки. `TableAppearanceView` владеет только поверхностью и местами карт; `BoardView` отвечает за карты и взаимодействия. `GameControlsView` берёт цвета из того же описания темы.

В будущем экран коллекции вызывает `await gameScene.setTheme(id)`. Метод сначала загружает весь комплект и возвращает `true` только после его применения. При ошибке загрузки остаётся прежнее оформление. Последний запрос выигрывает при быстрых переключениях. Пауза платформы не отменяет выбор; завершение сцены отменяет ожидающую загрузку.

Переключение не пересоздаёт раздачу, не сбрасывает отмену хода, не останавливает полёт карт и не меняет таймер. После успешного выбора экран коллекции должен сохранить `equipped.theme` через существующий механизм метаданных. `setTheme` сам не сохраняет выбор и не проверяет покупку/владение: это ответственность будущего экрана коллекции. При старте уже сохранённый `equipped.theme` применяется автоматически. Параметр URL `theme` имеет приоритет для предпросмотра и не перезаписывает сохранённое значение. Неизвестный идентификатор даёт стандартную тему.

## Проверки

```sh
node --test tests/*.test.ts tests/*.test.mjs
node node_modules/typescript/bin/tsc
node node_modules/vite/bin/vite.js build
```

Для браузерной проверки запустите Vite и выполните `node tests/browser/theme-runtime.mjs` с доступным Playwright и установленным Chrome. При внешнем расположении Playwright задайте `PLAYWRIGHT_MODULE` абсолютным путём к его пакету. `CASCADE_URL` позволяет указать другой адрес Vite. Тест подставляет доступ к экземпляру игры только в перехваченный браузером модуль; в production нет тестовых глобальных переменных.

Браузерный сценарий проверяет полную смену комплекта, паузу, повторные и быстрые переключения, сохранность раздачи, выдачу карт и отмену, изменение размера, сохранённую тему, предпросмотр и отказ/повтор загрузки. Скриншоты сохраняются в игнорируемой папке `artifacts/`.
