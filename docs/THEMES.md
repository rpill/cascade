# Темы игрового стола

Тема — поверхность, рубашка, палитра мест карт и игровых кнопок. Лица карт, правила, раскладка и главное меню независимы от темы. Источник истины — src/theme/ThemeRegistry.ts; JSON-манифесты рядом с изображениями служат документацией.

## Добавление темы

1. Положите файлы в public/assets/themes/<theme-name>/ и добавьте запись в THEMES. Ключ записи и id должны совпадать. ThemeId и список тем выводятся из реестра.
2. Задайте boardSurface, cardBack, surfaceScale, slots.palette и controls. Ключи текстур уникальны, URL относительные (./assets/...).
3. Для поверхности доступны tile (бесшовная фактура), cover (центральная обрезка) и framed (девять областей с сохранением углов и полного периметра). Последний требует surfaceSlices: {left,right,top,bottom} в пикселях источника. Необязательный surfaceCrop: {width,height} задаёт используемую область от верхнего левого угла до разбиения.
4. Рубашка изображает одну карту. Необязательный cardBack.crop: {x,y,width,height} исключает прозрачные поля импортированного изображения; Texture Frame создаётся до применения темы. Видимый контур масштабируется до размеров лица карты.
5. slots.palette содержит recess, edge, highlight, blackSuit, redSuit. Рамка и значок — отдельные изображения одинакового размера карты. Можно задать slots.frame с авторской рамкой без символов; масти и значок колоды остаются общими.
6. Цвета controls: surface, hover, ink, edge, labelSurface, labelInk, focus.

Общий шаблон рамки и значков имеет пропорции 216 × 302 и экспорт 432 × 604. Символ свободной колоды — карта, стрелка вниз и лоток — используется во всех темах. Подложка остаётся видимой под картами; расхождение контуров исправляется геометрией рубашки. Нижние слои колоды используют общий рисунок бумажного торца; орнамент находится только на верхней карте.

## Загрузка и переключение

getThemeAssets(theme) возвращает девять ресурсов: поверхность, рубашку, общий торец, рамку, четыре масти и значок колоды. TableSurfaceView отображает поверхность; TableAppearanceView — поверхность и места карт; BoardView — карты и взаимодействия. GameControlsView использует палитру темы.

Экран коллекции передаёт выбор координатору GameScene, который вызывает await setTheme(id). Метод загружает весь комплект перед применением; при ошибке остаётся прежняя тема. Последний запрос выигрывает при быстрых переключениях. Пауза платформы не отменяет выбор; завершение сцены отменяет ожидающую загрузку.

Переключение сохраняет раздачу, отмену хода, полёт карт и таймер. После успешной загрузки GameScene записывает equipped.theme через MetaSession и журнал операций. Покупку и владение проверяют чистые правила Economy; экран только показывает состояние и передаёт действия. При старте применяется сохранённая принадлежащая игроку тема. URL ?theme=<id> работает только в dev-сборке для временного предпросмотра; production игнорирует параметр. Неизвестный или недоступный сохранённый ID даёт базовую тему.

## Коллекция и магазин

Публикация отделена от регистрации рендера: `src/theme/ThemeCatalog.ts` содержит доступные игроку товары. Сейчас это бесплатная `walnut_study` и `navy_study` / `burgundy_club` по 300 монет. Покупается весь комплект, применение выполняется отдельной кнопкой. Экспериментальная тема из ThemeRegistry автоматически в магазин не попадает.

Для нового товара добавьте запись с названием, описанием, ценой, `previewUrl` и `cardBackUrl`, а также английский перевод названия и описания в `src/localization/English.ts`. Превью поверхности — отдельный лёгкий `shop-preview.webp` шириной 640 px; растровые рубашки используют `shop-card-back.webp` высотой 230 px. Полные текстуры загружаются при применении темы. Коллекция поддерживает фильтры «Все» / «Мои». Каталог прокручивается вертикально внутри панели; ширина карточек ограничена, в компактном горизонтальном меню карточки имеют горизонтальную компоновку. Переключение раздела возвращает список наверх, обновление состояния сохраняет прокрутку.

## Проверки

Проверьте 1915 × 953, 1366 × 768 и 844 × 390; пустой столбец, пустую колоду, наложение лица на рубашку, кнопки справа сверху и переключение темы.

```sh
node --test tests/*.test.ts tests/*.test.mjs
node node_modules/typescript/bin/tsc
node node_modules/vite/bin/vite.js build
```

При запущенном Vite выполните node tests/browser/theme-runtime.mjs с доступным Playwright и установленным Chrome. PLAYWRIGHT_MODULE задаёт абсолютный путь к пакету, CASCADE_URL — адрес сервера. Сценарий проверяет переключение, паузу, ошибки загрузки, сохранность раздачи, выдачу/отмену, размеры, слои рубашки и видимость подложки. Скриншоты находятся в игнорируемой папке artifacts/. Доступ к игре внедряется только в перехваченный тестовым браузером модуль.

`node tests/browser/economy-runtime.mjs` проверяет покупку обеих тем, применение, F5, награду за победу, сохранность раздачи/Undo и три размера экрана. `node tests/browser/economy-edgecases.mjs` проверяет ошибки чтения/сохранения и загрузки текстур, изоляцию профилей, повторный Daily, смену даты и компактный результат. SDK в этих тестах имитируется; проверка настоящего Yandex Player остаётся частью проверки релиза.
